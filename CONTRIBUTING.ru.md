# Участие в проекте

[English](CONTRIBUTING.md) | [Русский](CONTRIBUTING.ru.md)

Проект открыт для тестирования, вопросов, сообщений об ошибках и pull requests. Можно помочь, попробовав сценарии заказчика и исполнителя, сообщив о проблеме запуска, улучшив документацию или взяв задачу из Issues.

## Попробовать проект

Следуйте [README](README.ru.md). Для полного сценария используйте второй репозиторий и демонстрационные аккаунты. Начните с отдельной базы разработки и собственной локальной конфигурации.

## Вопросы и ошибки

Создайте [issue](https://github.com/proxymades/client-executor-server/issues/new/choose). Опишите свою цель, выполненные шаги, ожидаемое и фактическое поведение, версии инструментов. Для мобильных проблем укажите Android/iOS и устройство или симулятор. Прикладывайте только нужный для воспроизведения текст ошибки; удалите пароли, токены, строки подключения и персональные данные.

Вопросы и изменения можно обсуждать на русском или английском. В форме создания issue доступны шаблоны для обоих языков.

## Внесение изменений

1. Сделайте fork репозитория и создайте ветку для одного конкретного изменения.
2. Перед реализацией крупных изменений обсудите их в issue.
3. Следуйте существующей структуре кода и не включайте посторонние изменения в pull request.
4. Выполните проверки, относящиеся к изменению, и опишите результат в pull request.
5. Объясните изменение поведения и способ его проверки другим участником. Укажите, если проверки на устройстве, нативная сборка или проверки базы не выполнялись.

Проверки сервера:

```sh
npm run check
npm test
npx prisma validate
```

Изменения базы должны использовать генератор Prisma; не редактируйте SQL миграций вручную. Для интеграционных проверок нужна отдельная тестовая база. Если `TEST_DATABASE_URL` отсутствует, MySQL-тест пропускается: различайте успешные тесты resolvers/HTTP и проверку настоящей базы.
