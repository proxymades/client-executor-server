# Client Executor Server – CLEX

[English](README.md) | [Русский](README.ru.md)

Сервер с открытым исходным кодом для [приложения CLEX для заказчиков и исполнителей](https://github.com/proxymades/client-executor-mobile/blob/main/README.ru.md). Заказчики создают заказы на полиграфию, сувенирную продукцию и наружную рекламу; исполнители предлагают цену, получают работу и обмениваются отзывами после её завершения.

Попробуйте API вместе с мобильным приложением и демонстрационными аккаунтами. Вопросы, сообщения об ошибках и изменения приветствуются через [Issues](https://github.com/proxymades/client-executor-server/issues) и [руководство для участников](CONTRIBUTING.ru.md).

## Технологии

Node.js, Express 4, Apollo Server 3.7, GraphQL 16, Prisma 3.14, MySQL, bcrypt и необязательные уведомления Firebase Admin. Обновление зависимостей и улучшение локального запуска входят в текущую разработку.

Для встроенной загрузки `.env` нужен Node.js 22.16 или новее. Локальные проверки выполнены с Node.js 22.21.1 и npm 10.9.4.

## Настройка для разработки

```sh
git clone https://github.com/proxymades/client-executor-server.git
cd client-executor-server
```

Используйте отдельную пустую базу MySQL для разработки. Не направляйте команды изменения схемы или создания демонстрационных данных на существующую production-базу.

```sh
npm ci
cp .env.example .env
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Запишите сгенерированное значение в `APP_SECRET` в `.env`; задайте в `DATABASE_URL` строку подключения к своей базе MySQL для разработки. Не добавляйте `.env` в Git. Переменные, переданные средой запуска, имеют приоритет над значениями из файла.

Создайте структуру пустой базы для разработки по текущей схеме:

```sh
npm run generate
npx prisma db push
```

Исходные сгенерированные миграции включены в `prisma/migrations/` без редактирования. Их полное применение к новой базе MySQL ещё не проверено. `db push` используется здесь для локального первого запуска, а не как процедура миграции production-базы.

Запустите API и сервер изображений в двух терминалах:

```sh
npm run dev
```

```sh
npm run images
```

Адреса по умолчанию: `http://localhost:4000/graphql` и `http://localhost:5001/`. Команда `npm start` запускает API без nodemon. Новые папки для загрузок создаются по необходимости внутри настроенной папки ресурсов.

## Конфигурация

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Подключение MySQL для Prisma |
| `APP_SECRET` | Случайный секрет подписи JWT, не менее 32 символов |
| `PORT` | Порт GraphQL; по умолчанию 4000 |
| `IMAGES_PORT` | Порт сервера изображений; по умолчанию 5001 |
| `ASSETS_DIR` | Папка загрузок; путь относительно корня сервера, по умолчанию `public` |
| `CORS_ORIGINS` | Разрешённые браузерные origins через запятую; по умолчанию `http://localhost:8081` |
| `FIREBASE_ENABLED` | `true` или `false`; по умолчанию false |
| `FIREBASE_SERVICE_ACCOUNT` | Путь к исключённому из Git JSON сервисного аккаунта; абсолютный или относительно корня сервера |

Для push-уведомлений настройте собственный Firebase-проект и задайте `FIREBASE_SERVICE_ACCOUNT` либо используйте Google Application Default Credentials. Затем установите `FIREBASE_ENABLED=true`. При отключённых уведомлениях API не требует учётных данных Firebase. Уведомления отправляются после фиксации изменений базы; ошибка доставки не отменяет сохранённую операцию. Фактическая доставка FCM ещё не проверена.

Фотографии раздаёт отдельный статический сервер. Их URL публичны; загрузка требует подходящей роли аккаунта и владения заказом. Для JPEG/PNG установлен лимит 10 МБ, проверяется сигнатура файла, а замена выполняется через временный файл.

## Демонстрационные данные

Создание тестовых аккаунтов включается явно и предназначено только для базы разработки:

```sh
ALLOW_DEMO_SEED=true npm run seed:demo
```

| Роль | Телефон, вводимый в приложении | Пароль |
| --- | --- | --- |
| Заказчик | `1000000000` | `demo-password-123` |
| Исполнитель | `2000000000` | `demo-password-123` |

Это публичные демонстрационные учётные данные для отдельной локальной базы. Скрипт не перезаписывает существующие аккаунты и не сбрасывает их пароли. Он создаёт пример заказа в Алматы. В базе владельца проекта этот скрипт не запускался.

## Доступ и изменения состояния заказов

Личность авторизованного пользователя определяется по HS256 JWT со сроком действия семь дней. Запросы аккаунта требуют соответствующей роли заказчика или исполнителя. Чтение и изменение заказа заказчиком требуют владения этим заказом. Все ID заявок, включая предыдущую выбранную заявку, должны относиться к изменяемому заказу. Push-токены можно регистрировать и удалять только для авторизованного аккаунта.

Операции с заказами используют интерактивные транзакции Prisma и блокировку строки MySQL `FOR UPDATE`. Для Prisma 3.14 нужен preview-флаг генератора `interactiveTransactions`; его включение не меняет таблицы базы. Выбор исполнителя сбрасывает принятие других заявок только этого заказа. Завершение и отклонение одновременно меняют состояние заказа и заявки. Исполнитель не может отменить принятую или завершённую заявку; отзывы могут оставлять только участники завершённого заказа.

В multipart-запросах используйте заголовок загрузчика приложения `Apollo-Require-Preflight: true`, поскольку включена защита от CSRF.

## Проверки

```sh
npm run check
npm test
npx prisma validate
```

Команда `check` проверяет синтаксис сервера и GraphQL-схему. Если [мобильный репозиторий](https://github.com/proxymades/client-executor-mobile/blob/main/README.ru.md) находится в `../client-executor-mobile` или в исходной локальной папке `../clex`, она также проверяет его 44 GraphQL-документа.

Обычные тесты проверяют ограничения доступа, состояния заказов, отзывы, срок действия JWT, проверку загрузок и настоящий HTTP-запуск без Firebase. Тесты resolvers используют замену Prisma в памяти и не подтверждают блокировки или конкурентные операции MySQL. Интеграционный MySQL-тест пропускается, пока `TEST_DATABASE_URL` не указывает на отдельную тестовую базу с этой схемой:

```sh
TEST_DATABASE_URL='mysql://test-user:test-password@127.0.0.1:3306/clex_test' npm test
```

Интеграционный тест создаёт и удаляет только собственные записи. Он проверяет одновременные предложения, одновременный выбор исполнителя и повторные отзывы. Локально он не запускался, поскольку отдельный экземпляр MySQL был недоступен.
